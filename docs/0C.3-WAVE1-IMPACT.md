## A correction to this report's own first run

My first 30-day replay returned **`max_decrease_any_day: 26`** and I nearly
reported it. It was wrong, and the error is worth recording because it is the
same class of mistake this whole workstream is about.

The old query was `.gte(today − 7)` with **no upper bound**. On a real "today"
that is harmless — there are no rows after today. But replaying it against a
*past* day counts every row from that day forward, so the "old" count absorbed
weeks of subsequent logs and the apparent decrease exploded. The number
described my simulation, not production.

Bounding the old window at `d` — which is what actually ran — gives the table
above, and the maximum decrease is 1, as the arithmetic requires. **A number
that does not match what the arithmetic permits is a bug in the measurement,
not a discovery.**

| Surface | Before | After |
|---|---|---|
| Weekly Diagnosis line | `Studied 8 of 7 days (Xh logged)` | `Studied 7 of 7 days (Xh logged)` |
| Weekly Diagnosis, the 1 → 0 group (10 students) | `⚠️ Studied 1 of 7 days` | `⚠️ Studied 0 of the last 7 days — the week slipped entirely.` |
| Buddy consistency flag | unchanged today | 0–3 students/day may newly trip it |
| Weekly Signal card, buddy briefing, AI drafts | count one lower where affected | same |

**The 1 → 0 group is the most visible copy change**: ten students move from a
mild warning to the "week slipped entirely" sentence. Both are true statements
about the corrected window — the day they logged is genuinely the eighth day
back, outside the week being described — but the *tone* steps up, and it does so
for the students already least engaged.

That is a product judgement, not a correctness one, and it is the one thing in
this report I would put in front of you rather than decide.

## Method

`SELECT` only. Demo and test accounts excluded via `is_test_account`. Counts
use `COUNT(DISTINCT report_date)`, which equals row count under the live
`UNIQUE (student_id, report_date)` constraint. The mentor-flag threshold is
read from `buddy/(dashboard)/students/[id]/page.tsx` (`< 3`), and buddy status
from `profiles.buddy_id`.
